## 3. 数据层：行情爬取

默认数据源为 **Tushare Pro**（按交易日批量拉全市场，比 Baostock 逐股 socket 更稳）。回退 Baostock：

```bash
export QUANT_DATA_SOURCE=baostock
# 或
python dataScrapper.py daily-quick --source baostock
```

### 3.0 Tushare 配置（首次）

```bash
cp docs/trading-system/tushare.yaml.example docs/trading-system/tushare.yaml
# 编辑 tushare.yaml 填入 token；或 export TUSHARE_TOKEN=...
pip install -r requirements.txt
```

### 3.1 常用命令

```bash
# 补全到指定日期（从库内最新日期的下一天开始）
python dataScrapper.py backfill --end 2026-05-16

# 收盘后增量更新（推荐每日使用）
python dataScrapper.py daily

# 仅重试区间内仍缺失的股票（断点续传，网络中断后用）
python dataScrapper.py retry-failed --start 2025-11-29 --end 2026-05-16

# 全量重下近 N 年（耗时长，慎用）
python dataScrapper.py full --years 10
```

### 3.2 查看数据状态

```bash
sqlite3 stock_data.db "SELECT MAX(trade_date) FROM stock_daily;"
```

### 3.3 自动定时更新（macOS）

已配置 **每个交易日 17:00** 执行 `scripts/daily_stock_update.sh`：

1. `dataScrapper.py daily` — **后台**拉新日 + 近 14 日缺口；每 60s 检查覆盖率
2. 下列任一条件即**停止等待补数、继续后续步骤**：覆盖率 ≥92%；补数进程退出；**30 分钟**计数不增长（卡死）；总等待 **150 分钟**（超时）
3. 仍未达标 → 最多 3 轮 `retry-failed`
4. `scripts/trading/daily_briefing.py --date 最新交易日` — 生成日报
5. `scripts/trading/send_briefing.py` — 推送**公开版**到飞书 + 个人微信（需 `notify.yaml`）

```bash
scripts/install_launchd.sh install   # 安装/重装
scripts/check_launchd_daily.sh       # 诊断
launchctl kickstart -k gui/$(id -u)/com.quant.stock-daily  # 手动测试
scripts/install_launchd.sh status
scripts/install_launchd.sh uninstall

# 手动跑一次（与定时任务相同）
/bin/bash scripts/daily_stock_update.sh

# 仅拉新日、不校验全市场（约 1 分钟，调试用）
.venv/bin/python dataScrapper.py daily-quick
```

日志：`logs/launchd_daily.log`、`logs/launchd_stderr.log`  
日报：`docs/trading-system/journal/YYYY-MM-DD-日报.md`（私人版）、`…-日报-公开.md`（可分享）

**推送飞书 + 个人微信**（可选）：

```bash
cp docs/trading-system/notify.yaml.example docs/trading-system/notify.yaml
# 编辑 notify.yaml：feishu_webhook、pushplus_token（或 serverchan_sendkey）

# 预览摘要不发送
.venv/bin/python scripts/trading/send_briefing.py --date 2026-06-02 --dry-run

# 手动推送
.venv/bin/python scripts/trading/send_briefing.py --date 2026-06-02
```

| 渠道 | 配置项 | 获取方式 |
|------|--------|----------|
| 飞书群 | `feishu_webhook` | 群设置 → 群机器人 → 自定义机器人 → Webhook |
| 个人微信 | `pushplus_token` | [PushPlus](https://www.pushplus.plus) 注册 → 首页复制 token → 微信关注「pushplus 推送加」 |
| 备选 | `serverchan_sendkey` | [Server酱](https://sct.ftqq.com) SendKey |

`notify.yaml` 含密钥，已加入 `.gitignore`，勿提交仓库。  
推送内容：**综合优选详情** + **次日执行清单（E-009）** + 各策略个股名称摘要。

**手机更新持仓**：见 [手机与GitHub工作流.md](./手机与GitHub工作流.md)（私有库 + Cloud Agent 改 `account.yaml` → Mac `scripts/sync_from_github.sh`）。

**定时任务不执行时（最常见）**：项目在 `Documents` 下，launchd 读不了 `.venv`。  
系统设置 → 隐私与安全性 → **完全磁盘访问权限** → 添加并勾选 **`/bin/bash`** 与 **`.venv/bin/python`**，然后 `launchctl kickstart ...` 测试。

### 3.4 网络「接收错误」技巧

| 现象 | 原因 | 处理 |
|------|------|------|
| 连续 `网络接收错误` | Baostock 长连接/session 失效 | 停止任务，稍后跑 `retry-failed` |
| 已爬 4000+ 只后全失败 | 同上，非家里断网 | 不要从头 `backfill`，用续传 |

爬虫已内置：**自动重试、定期重连、名称缓存、0.5s 间隔**。

## 4. 策略层：月度主线 + 龙头

### 4.1 规则摘要

详见 `playbooks/theme.md`。

| 步骤 | 规则 |
|------|------|
| 何时出手 | 题材/板块：**5 日强确认**（上涨日 ≥ 4，5 日涨幅 ≥ 4%，成交额放大）；**收盘 scan → 次日执行** |
| 买什么 | 池内 **1～2 只龙头**（涨幅 + 成交额 + 换手率综合得分） |
| 何时空仓 | 无合格主线、龙头破 20 日线、板块强势衰竭等 |
| 多条主线 | 只做 **5 日板块涨幅最高** 的一条 |
| 执行节奏 | **收盘后 scan** → **次日 10:30 后** 按 E-009 执行清单买入 |

**默认 setup_tag**：`monthly_theme_dragon`  
**默认规则 id**：`E-002`（见 `playbooks/entry.md`）

### 4.2 命令

```bash
# 建议先补行业（可选，全量约 1～2 小时）
python monthly_theme_dragon.py refresh-industry --limit 100   # 试跑
python monthly_theme_dragon.py refresh-industry               # 全量

# 每晚收盘后扫描（决定次日策略）
python monthly_theme_dragon.py scan
python monthly_theme_dragon.py scan --date 2026-05-15
# 输出含【次日策略】：可买 → 次日开仓；仅观察 → 次日不追

# 每晚交易日报（推荐）
python scripts/trading/daily_briefing.py
# → docs/trading-system/journal/YYYY-MM-DD-日报.md

# 回测
python monthly_theme_dragon.py backtest --start 2024-01-01 --end 2026-05-15
```

### 4.3 题材池

- 总览：`themes/market_themes_overview.md`
- 17 条预置题材、约 170+ 只成分股：`themes/manual_themes.yaml`（可手工增删）
- **热点 ≠ 可交易**：须通过扫描的 T-001 量价条件

### 4.4 扫描结果含义

| 输出 | 操作 |
|------|------|
| 无合格主线 → 空仓 | 次日不新开仓（T-004） |
| 有主线 + 仅【观察】 | 当晚记下龙头，**次日不追** |
| 有主线 + 【可买】 | **次日开盘**买入；成交记入 `trades.csv` |

## 5. AI 工作流：复盘 / 入库 / 进化

### 5.1 Skill 是什么

路径：`.cursor/skills/short-term-trading-evolution/`

**不会**把 PDF「训练进模型大脑」；而是让 AI **读写你仓库里的固定文件**，形成可版本化的交易知识。

进化闭环：

```text
教材/PDF → playbooks → trades.csv → metrics → journal 复盘 → changelog → 改规则/代码
```

### 5.2 四类文件（AI 的「燃料」）

| 文件 | 谁维护 | 作用 |
|------|--------|------|
| `constitution.md` | 你（慎改） | 仓位、止损、禁止 ST |
| `playbooks/*.md` | AI 入库/进化时改 | 可执行规则，每条有 **id** |
| `trades.csv` | **你必须填** | 成交事实 |
| `metrics/latest.json` | 脚本生成 | 胜率、按 setup 分组 |

```bash
python scripts/trading/update_metrics.py
```

### 5.3 工作流 A：知识入库（操盘笔记 / PDF / 战法）

**操盘笔记（你已打开的那份）**

1. 全文粘贴到 `docs/trading-system/knowledge/操盘笔记.md`（`---原文开始---` 下方）  
   或：在 Cursor 里 **另存为** 该路径  
2. 使用下方 [入库](#入库) 模板，@ `操盘笔记.md`  
3. 确认后规则进入 `playbooks/notes.md`（`N-001`…），映射见 `操盘笔记-映射表.md`

**其他教材**

1. 摘要保存为 `knowledge/书名-summary.md`
2. Cursor 中 @ 该文件，使用 [入库模板](#入库)
3. 你审阅 → 回复 **「确认入库」** 后才写入 playbook

### 5.4 工作流 B：每日复盘

1. `dataScrapper.py daily`（若定时任务已跑可跳过）
2. `monthly_theme_dragon.py scan`
3. 有成交 → 写入 `trades.csv` → `update_metrics.py`
4. Cursor 使用 [复盘模板](#复盘)

复盘应绑定规则 id，例如：`violation:T-002`、`good:T-004`（空仓也是正确执行）。

### 5.5 工作流 C：进化（改规则）

| 样本量 | 可以做什么 |
|--------|------------|
| &lt; 10 笔 | 只讨论，不改规则 |
| ≥ 10 笔 | 讨论某 setup 好坏 |
| ≥ 30 笔且胜率 &lt; 40% | **提议** 降级/删除 setup |
| 改 constitution | 必须你明确说「同意改宪法」 |

流程：AI 先出 **「进化提议」草案** → 你回复 **「确认进化」** → AI 改 playbook + changelog（必要时改代码）。

详见：`.cursor/skills/short-term-trading-evolution/evolution-protocol.md`

### 5.6 触发 Skill 的关键词

`短线`、`复盘`、`胜率`、`交易系统进化`、`playbook`、`入库`、`进化`

## 6. 每日 / 每周节奏

### 每个交易日（收盘后约 15 分钟 → 定次日计划）

| 顺序 | 动作 |
|------|------|
| 1 | 确认 `stock_data.db` 已更新（`daily` 或 launchd） |
| 2 | （可选）发券商截图 → Cursor 更新 `account.yaml` |
| 3 | `python scripts/trading/daily_briefing.py` → 生成 `journal/日期-日报.md` |
| 4 | 阅读日报：**仓位 / 可买 / 自选 / 止损·MA20 出场** |
| 5 | **次日 10:30 后**按日报 **第十节执行清单（E-009）** 买入；有成交 → `trades.csv` → `update_metrics.py` |
| 6 | Cursor：「今日复盘」（绑定规则 id） |

### 每周五（约 20 分钟）

- 阅读 `metrics/latest.json` 的 `by_setup`
- Cursor：「进化提议」
- 确认后更新 playbook / `manual_themes.yaml`

### 每月

- 新教材 → `knowledge/` → 入库
- 检查题材池是否过时

## 7. 使用技巧（让系统变强）

### ✅ 推荐做法

1. **每笔平仓都记 `trades.csv`**，`setup_tag` 与策略一致  
2. **复盘写规则 id**，不写「感觉不好」  
3. **进化一次只改 1～3 条规则**，changelog 写清数据依据  
4. **规则与代码同步**：改 `theme.md` 参数时，同步 `monthly_theme_dragon.py` 的 `ThemeConfig`  
5. **空仓也复盘**：记 `good:T-004`，强化纪律执行  
6. **网络中断用 `retry-failed`**，不要从头全量爬  

### ❌ 避免做法

- 只聊天不更新 `trades.csv` / `journal`  
- 一次塞整本 PDF 不摘要  
- 亏一笔就要求大改策略  
- 从不跑 `update_metrics.py` 或 `scan`  
- 样本不足时强行「进化」  

### trades.csv 示例

```csv
trade_id,symbol,setup_tag,primary_rule_id,entry_date,exit_date,entry_price,exit_price,pnl_pct,notes
T001,sh.601138,monthly_theme_dragon,E-002,2026-05-10,2026-05-14,18.2,19.1,4.9,T02龙头
```

| 列 | 说明 |
|----|------|
| setup_tag | 与 playbook 一致，主策略用 `monthly_theme_dragon` |
| primary_rule_id | 如 `E-002`、`T-002` |
| pnl_pct | 盈亏百分比，**平仓后**再填 |

## 9. 常见问题

**Q：扫描一直「无合格主线」？**  
- 检查 `manual_themes.yaml` 是否有标的；可选跑 `refresh-industry`  
- 规则偏严（15/20 上涨日 + 8% 涨幅）时，多数日子空仓是正常的  

**Q：metrics 全是 null？**  
- `trades.csv` 需有**已平仓**记录（填了 `exit_date` 和 `pnl_pct`）  
- 跑 `python scripts/trading/update_metrics.py`  

**Q：Skill 没生效？**  
- 对话里带上「复盘」「进化」等触发词，或 @ `docs/trading-system/` 下文件  

**Q：MomentumTrend 还用吗？**  
- playbook 中为 **watch**，默认实盘逻辑是 `monthly_theme_dragon`  

**Q：数据补全要多久？**  
- 全市场约 5000 只 × 0.5s ≈ 40 分钟以上；用 `retry-failed` 续传
